# RLM Billing

## Instructions

### Step 1: Identify the billing task
- **Billing setup**: BillingPolicy, BillingTreatment, BillingTreatmentItem, BillingSchedule, AccountingPeriod
- **Invoice generation**: `Create Billing Schedules From Billing Transaction Action`, `Post Draft Invoice Action`
- **Credit / Debit memos**: `Issue Credit Memo Action`, credit memo application, `Post Draft Credit Memo Action`
- **Payments**: `Apply Payments and Credits by Rules Action`, PaymentSchedule, PaymentTerm
- **Billing run**: `InvoiceBatchRun`, `BillingBatchScheduler`, `Post Draft Invoice Batch Run Action`
- **Write-offs**: `Write Off Invoices Action`

### Step 2: Billing object deployment sequence
Deploy in this order:
1. `AccountingPeriod` — define fiscal periods before billing runs
2. `BillingPolicy` — billing frequency, proration rules
3. `BillingTreatment` (→ BillingPolicy)
4. `BillingTreatmentItem` (→ BillingTreatment)
5. `BillingArrangement` (→ Account, BillingPolicy)
6. `BillingArrangementLine` (→ BillingArrangement, Order/QuoteLineItem)
7. `BillingSchedule` — generated by Create Billing Schedules action
8. `BillingScheduleGroup`
9. `BillingPeriodItem` — individual billing period entries
10. `Invoice` — generated by batch run or Post Draft Invoice action
11. `InvoiceLine` (→ Invoice, BillingSchedule)
12. Tax objects: `TaxEngine`, `TaxPolicy`, `TaxTreatment`, `TaxTreatmentItem`
13. Credit/Debit: `CreditMemo`, `CreditMemoLine`, `DebitMemo`, `DebitMemoLine`
14. Payment: `PaymentSchedule`, `PaymentSchedulePolicy`, `PaymentScheduleTreatment`

### Step 3: Create billing schedules from an order
After order activation, create billing schedules:

Flow invocable: `Create Billing Schedules From Billing Transaction Action`
- Input: `billingTransactionId` (the Order or OrderItem)
- Output: list of `BillingSchedule` records created

Or via Business API:
```
POST /services/data/v66.0/commerce/billing/billing-schedules
Body: { "billingTransactionId": "801..." }
```

### Step 4: Generate and post invoices
Two-step process:

**Step 4a: Create draft invoices via batch run**
```apex
// Schedule or call billing batch
BillingBatchScheduler scheduler = new BillingBatchScheduler();
// Or use the InvoiceBatchRun record with criteria
```

Or via invocable: `Post Draft Invoice Batch Run Action`
- Input: `invoiceBatchRunId`

**Step 4b: Post draft invoices**
Flow invocable: `Post Draft Invoice Action`
- Input: `invoiceId` or list
- Output: posted `Invoice` records with `Status = Posted`

Business API:
```
POST /services/data/v66.0/commerce/billing/invoices/{invoiceId}/post
```

### Step 5: Apply payments and credits
**Apply a payment to invoices**:
Flow invocable: `Apply Payments and Credits by Rules Action`
- Input: `paymentId`, `invoiceId` list, `applicationRules`
- Output: `PaymentLineInvoice` records created

**Apply a credit memo**:
Flow invocable: `Apply Credit Action`
- Input: `creditMemoId`, `invoiceId`
- Output: `CreditMemoInvApplication` records

### Step 6: Issue and post credit memos
1. `Issue Credit Memo Action` — creates a draft CreditMemo from an invoice
   - Input: `invoiceId`, `creditReason`, `lines[]`
   - Output: `creditMemoId`
2. `Post Draft Credit Memo Action` — posts the draft to finalize it

### Step 7: Void and write off
**Void a posted invoice**: `Void Posted Credit Memo Action` or Business API `POST /invoices/{id}/void`
- Only voidable if no payments applied

**Write off uncollectible invoices**: `Write Off Invoices Action`
- Input: `invoiceIds[]`, `writeOffReason`, `accountingPeriodId`
- Creates `GeneralLedgerAcctAsgntRule` entries for write-off accounting

### Step 8: Tax integration
Revenue Cloud supports external tax engines via `TaxEngine` + `TaxEngineProvider`.

To integrate a tax engine:
1. Create `TaxEngine` record with provider connection details
2. Implement `TaxEngineAdapter` Apex interface
3. Link `TaxTreatment` to products via `TaxTreatmentItem`
4. Tax is calculated at invoice posting time via `TaxEngineInteractionLog`

### Step 9: Grand Total after configuration
After PST saves a product configuration, query the Quote's Grand Total:
```apex
Quote q = [SELECT GrandTotal, TotalPrice, LineItemCount FROM Quote WHERE Id = :quoteId];
// GrandTotal includes all BOM components + taxes + discounts
// This is the figure to communicate to customers
```

## Common Issues

### Error: "SINGLE_EMAIL_LIMIT_EXCEEDED" in Apex logs
Cause: Developer/trial org 15 single-email/day limit hit.
Solution: This silently drops the email. Monitor `Messaging.SingleEmailMessage` sends in tests. Use sandbox with higher limits for volume testing.

### Invoice not generated — BillingSchedule status shows "Pending"
Cause: Billing batch run not triggered, or AccountingPeriod not active for the billing date.
Solution: Verify `AccountingPeriod.Status = Active` covers the billing date. Run `BillingBatchScheduler` or manually trigger `Post Draft Invoice Batch Run Action`.

### Error: "Cannot void invoice with applied payments"
Cause: A payment has been applied to the invoice.
Solution: Unapply the payment first via `Unapply Payment Action`, then void the invoice.

### Credit memo not applying to invoice
Cause: `CreditMemo.Status != Draft` or amount mismatch.
Solution: Credit memos must be in Draft status before posting. Verify `CreditMemoLine` amounts.

### Tax not calculated on invoice
Cause: `TaxEngine` not connected or `TaxTreatment` not linked to product.
Solution: Check `TaxEngineInteractionLog` for error details. Verify `TaxTreatmentItem.ProductId` matches the invoiced product.

## Examples

### Example 1: Full order-to-invoice flow
User says: "Generate an invoice for order X"

1. Verify order `Status = Activated`
2. Call `Create Billing Schedules From Billing Transaction Action` with `orderId`
3. Verify `BillingSchedule` records created
4. Call `Post Draft Invoice Batch Run Action` or `Post Draft Invoice Action`
5. Query `Invoice.Status`, `Invoice.TotalAmount`
6. Return: invoice generated, Invoice # = INV-XXXX, Total = $Y

### Example 2: Issue and apply a credit memo for a cancelled service
1. Call `Issue Credit Memo Action` (invoiceId, reason = "Service Cancellation")
2. Call `Post Draft Credit Memo Action` (creditMemoId)
3. Call `Apply Credit Action` (creditMemoId, invoiceId)
4. Return: credit of $X applied to invoice INV-XXXX

### Example 3: Check outstanding balance for an account
1. Query `Invoice` WHERE `AccountId = :accountId AND Status = 'Posted' AND Balance > 0`
2. Sum `Balance` across invoices
3. Query `BillingArrangement` for payment terms
4. Return: N open invoices totaling $X, next due date = Y
