# Usage Management — Object Reference

All objects that make up the Usage Management module (Ch. 11, RLM Developer Guide v68.0, Winter '27).

> **v68 re-baseline note (2026-09-11):** Every field table in this file was re-verified against the v68.0
> Usage Management Standard Objects section (printed pp. 1989–2072) and corrected. Several fields present
> in the prior (v66) version of this file do not exist on these objects in the documented schema (e.g.
> `IsActive`, `DeveloperName`, `RoundingMethod`, `Scale`, `RenewalType`, `RolloverType`, `OverageType`,
> `CommitmentQuantity`, `GrantedQuantity`/`ConsumedQuantity`/`RemainingQuantity`/`ExpirationDate` on
> `UsageEntitlementBucket`, `BillableAmount` on `UsageBillingPeriodItem`, and others) — these have been
> replaced with the documented field names below. `TransactionJournal`, `UsageResourcePolicy`, and
> `UsageResourceBillingPolicy` have been added as they were missing from the prior version.

---

### UsageCommitmentPolicy
Represents the set of rules that determine how commitments are applied to a usage resource. Available in API v65.0+.

| Field | Type | Description |
|---|---|---|

### UsageOveragePolicy
Represents the set of rules that determine the management of a usage resource's units consumed beyond the granted limit. Available in API v65.0+.

| Field | Type | Description |
|---|---|---|
| `Name` | String | The name of the usage overage policy |
| `OverageChargeable` | Picklist | `No` \| `Yes` — whether overconsumption beyond the granted quantity is charged |

> **Correction:** This object does **not** have `OverageType`, `OverageRate`, or `UsageResourceId` fields — it
> is a simple chargeable/not-chargeable flag. The link to a resource happens via
> `UsageResourcePolicy.UsageOveragePolicyId`, and the actual overage rate is calculated during rating
> (see `UsageRatableSummary.NetUnitRate`), not stored on this policy.
